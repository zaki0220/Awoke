# Awoke (地震情報 Discord 通知サービス)

## 概要

P2P地震情報のWebSocketから気象庁の地震情報、津波情報、緊急地震速報（警報）を受信し、Discord Webhookへ通知するサービス。

本書は実装前の仕様案。P2P地震情報は非公式の情報提供サービスであるため、防災判断には気象庁や自治体の公式情報を優先する。緊急地震速報は予測を含み、観測された震度とは区別する。

## 動作環境

- Rocky Linux 9
- 固定グローバルIP、ドメインなし
- P2P地震情報とDiscordへのアウトバウンド通信およびDNS名前解決が必要
- 外部公開ポート、ドメイン、固定グローバルIPは本サービスの動作には不要

## 構成案

```text
P2P地震情報 WebSocket → 常駐サービス → Discord Webhook
                            ↕
                          SQLite
```

- Pythonで実装し、systemdで常駐・自動起動する。
- SQLiteに通知済み情報、情報の種類・識別子とDiscordのメッセージIDの対応、および送信・編集待ち情報を保存する。
- Webhook URLは秘密情報として扱い、アクセス権を制限した設定ファイルに保存する。ログやGitには含めない。

## 受信情報

- WebSocket: `wss://api.p2pquake.net/v2/ws`。配信される情報のうち、次の3種類を処理する。
  - `551`: 観測後の地震情報
  - `552`: 津波警報・注意報などの津波情報
  - `556`: 緊急地震速報（警報）。すべての緊急地震速報（予報）を受信するものではない。
- 過去情報のHTTP API: `https://api.p2pquake.net/v2/history?codes=551,552,556`。3種類の初回の基準作成や再接続後の照合に利用する。
- 同一情報が複数回配信される場合は、配信情報の`id`で重複を除く。`id`は更新前後の同一地震の識別子とは限らない。
- 更新報を既存メッセージに対応付ける方法は情報の種類ごとにP2P地震情報の仕様と実データを確認して決定する。`556`は`issue.eventId`の利用を検討する。曖昧な対応付けによる誤編集は避け、識別できない場合はログに記録する。
- 地域・観測点ごとの震度は、発表内容に応じて`points`に含まれる。地域と観測点は`isArea`で区別する。

## 通知仕様案

### 情報ごとの通知条件

- **地震情報（551）**: 全国の最大震度が設定値以上の場合に通知する。例えば設定値が震度4なら、震度4以上を通知する。
  - 震度は `1 < 2 < 3 < 4 < 5弱 < 5強 < 6弱 < 6強 < 7` の順で比較し、`maxScale`を震度に対応付ける。震度情報なしや不明な値は震度0とみなさず、ログに記録する。
  - 発生時刻、震源地、最大震度、マグニチュード、深さ、取得できた場合は津波情報、情報源を含める。津波情報が不明の場合は「心配なし」と推測しない。
  - 初報が設定値未満で未通知の場合でも、更新後に設定値以上になれば新規メッセージを送信する。通知後に設定値未満になった場合も既存メッセージを編集して訂正を反映する。
- **津波情報（552）**: 津波注意報・津波警報・大津波警報を、震度の設定値に関係なく通知する。取得できる予報区、警報・注意報の種類、予想される高さ、到達予想時刻などを表示する。
  - 更新・解除を受信した場合は状態を反映する。解除は空の予報区一覧を使って判定せず、`cancelled`を確認する。
- **緊急地震速報（556）**: 警報を震度の設定値に関係なく通知する。取得できる震源、予想震度、対象地域などを表示し、予測であることを明記する。
  - 更新・取消を受信した場合は状態を反映する。取消は`cancelled`を確認する。

### 共通の扱い

- 速報（556）と観測後の地震情報（551）は、同じ地震に関するものでも別メッセージにする。津波情報（552）も別メッセージにする。
- 初回起動時の過去情報は3種類とも通知せず、以降の判定の基準として記録する。既に発表されている警報・注意報も初回の履歴からは通知されない。基準作成とWebSocket受信が重なる間の情報を取りこぼさない手順は実装前に検証する。
- 初報の送信時はWebhookに`wait=true`を指定し、返されたメッセージIDを情報の種類と識別子に対応付けてSQLiteに保存する。
- 通知済みの情報に重要な更新・訂正・取消・解除があった場合は、新しいメッセージを送信せず既存のメッセージを編集する。編集対象となる変更項目と、更新・解除を正しく対応付ける方法は実装前に確定する。
- メッセージの編集は新規メッセージではないため、Discordで再度通知されることは期待しない。

## 地図表示仕様案

- 背景地図にはNatural EarthのLarge scale（1:10m）Physical「Land」を使用する。事前にダウンロードしてサーバーに保存し、地図画像の生成時にローカルから読み込む。
- P2P地震情報の震源座標や地域別情報を背景地図に重ね、地図画像を生成してDiscordのメッセージに添付する。震源座標が不明な場合は震源を表示しない。
- 地域境界には事前にダウンロードした気象庁のGISデータを利用する。551・556の地域表示は「地震情報／細分区域」、552は「津波予報区」を候補とし、受信する地域名との対応を実装前に確認する。
- 観測震度と予想震度、津波情報は区別して表示する。地域を正確に対応付けられない場合は誤った塗り分けを行わず、ログに記録する。観測点ごとの表示には別途座標データと利用条件の確認が必要。
- 更新報では地図画像も更新し、既存のDiscordメッセージに反映する。添付画像の更新方法はDiscordの仕様に従う。
- 地図画像には必要な出典と加工した旨を表示する。Natural Earth・気象庁GISの利用条件、Discordへの画像送信に伴う申請の要否を実装前に確認する。別データ間の海岸線や境界のずれ、島の欠落も検証する。
- 地図データの読み込みや画像生成に失敗した場合はエラーを記録し、地震・津波情報の通知自体はテキストで行う。

## 障害対応・運用

- WebSocket切断時は、待機時間を徐々に延ばしランダムな揺らぎを加えて再接続する。接続監視はP2P地震情報の仕様に従い、地震情報が届かないことだけを切断と判断しない。
- 再接続後はHTTP APIの履歴と保存済み情報を照合し、停止中の新規情報を可能な範囲で補完する。取得可能な履歴には制限があり、停止中の全情報の復元は保証できない。
- APIのレート制限と利用条件を守り、不要な接続や履歴取得を避ける。
- Discordへの一時的な送信失敗は再試行する。HTTP `429`ではDiscordが示す待機時間に従う。Webhook無効などの恒久的なエラーは連続送信せず、ログや監視で検知できるようにする。
- メッセージの削除やWebhookの無効化などで編集できない場合はエラーを記録する。新規メッセージで代替するかは実装前に確定する。
- 送信結果が不明な状態で再試行した場合、重複通知が発生する可能性がある。
- 専用の一般ユーザーで実行し、接続状態や送信結果を`journalctl`で確認できるようにする。長時間の切断や送信失敗は、可能ならDiscord以外の経路でも監視する。

## 検証項目

- 震度の正規化と、設定値ちょうど・設定値超過の境界判定
- 初回起動時の過去情報の扱いと、同じ地震の更新・重複判定
- 初回の基準作成中に届く情報と、履歴の照合による復旧
- 通知済みメッセージの編集、震度の閾値をまたぐ更新、編集できない場合の扱い
- 551と556の別メッセージへの通知、556の更新・取消、552の更新・解除
- 地図への震源・地域情報の重ね合わせ、画像更新、地図データの読み込みや画像生成の失敗時のテキスト通知
- WebSocket切断、再接続、サービス再起動後の復旧
- Discordの送信失敗・レート制限時の再試行
- Rocky Linux 9でのsystemd自動起動とテスト用Webhookへの送信
